# Agent 1 design and reproducibility

## Pipeline

1. Resolve English/Arabic intent to taxonomy categories and a supplied or resolved AOI.
2. Validate source coverage, declared use, license and attribution policies.
3. Apply robots checks, endpoint rate limits, shared Retry-After cooldown and bounded transport retries.
4. Capture source records and bind timestamps, source identity/version and dataset hashes to snapshot descriptors.
5. Normalize names, categories, coordinates, address/contact fields and field-level provenance.
6. Enrich missing language fields using versioned deterministic rules; preserve source spellings and identify generated values.
7. Validate geometry and AOI inclusion; queue unresolved records and identify explicitly derived coordinates.
8. Conflate compatible records, reconcile internal identities and compute additions, updates, removals, unchanged records and field-level differences.
9. Write audit artifacts, publish PostGIS and styled GeoServer layers, and verify WFS/WMS, CRS, metadata and attribution.

## Identity and published schema

The backing record table retains a stable internal identity for reconciliation and offline replay. Its public primary key is integer `id`, generated by a serial sequence. Updates and reactivation preserve this ID; removal marks the internal record inactive. The public view and GeoServer layer expose `id` rather than the internal `stable_id`.

Required canonical fields remain even when source values are absent. Optional columns are published when any active record supplies a meaningful value. Zero and false remain meaningful. Full audit fields remain in the backing record table and capture files. Schema migration is transactional; GeoServer attribute refresh targets only the relevant datastore.

## Snapshot safety and transport

The durable SQLite latest-snapshot store scopes datasets by source/endpoint, AOI geometry and sorted category IDs, independently of request language. It rejects snapshot downgrades, identity mismatches, invalid timestamps replacing known versions, and equal timestamps with different datasets. Identical snapshots can be processed repeatedly.

Included live sources use `latest_available`: data beyond the configured age threshold is processed with its date and older-data status disclosed. Strict age enforcement is selectable. Explicit historical processing uses `--snapshot-from`, preserves capture integrity and does not claim live freshness. Both policies retain relative-version protection.

Source acquisition completes before incremental changes or publication. An exhausted timeout budget, cancellation or invalid response reports failure without silently using stale data. Streaming reads and retries are bounded; workers handling the same query share snapshot state.

## Names and geometry

OSM multilingual, official, short and alternate fields are resolved by the source adapter. Unicode comparison keys normalize diacritics, tatweel and Arabic/Persian variants while source values and original payloads remain available. Missing language fields use versioned `rules-v3`; uncertain transliterations retain review reasons and confidence. Genuinely unnamed records remain explicitly unnamed.

Source point coordinates are preserved. Optional licensed geocoding is marked derived with confidence capped at 0.5. Explicitly permitted OSM way/relation centers are footprint-derived with confidence capped at 0.35. Missing or invalid coordinates are queued rather than fabricated. AOI polygon holes and multipolygons are respected.

## Conflation and replay

New processing uses conflation version 3; historical versions 1 and 2 remain replayable. Distance, category and phone guards constrain merges. Known conflicting phone numbers block merges, including a bridge through a record without a phone. Address similarity is diagnostic.

Capture integrity binds input records, source registry, prior records, taxonomy, transformation metadata and final canonical records with hashes. Replay reconstructs normalization, versioned conflation and identity reconciliation from captured transformed records. It compares canonical structures and hashes without network requests, LLM calls, translation regeneration or clock-dependent freshness checks. Execution timings are outside the canonical records.

## Evaluation and deployment

The package supports CLI and structured `poi_harvester.agent.invoke(payload)` invocation. Normal runs publish; missing required inputs request clarification. Explicit file-only previews remain available. Runtime credentials load from ignored `.env` files or process environment.

Automated tests, human-review input/ratings manifests and project-authored fixtures are shipped for reproducibility. Evaluation generates local evidence and criterion status rather than inventing official scores. The 10K synthetic grid tests processing/publication load; it does not certify real-world POI throughput or positional accuracy. Performance stages and available host CPU/RAM are recorded separately.
